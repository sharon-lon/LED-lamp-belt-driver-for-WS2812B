# LED Lamp Belt Driver for WS2812B (8051 MCU)

A lightweight WS2812B LED strip driver implemented on an 8051 MCU using cycle-accurate GPIO bit-banging.

This project drives WS2812B LEDs without dedicated hardware peripherals. The communication waveform is generated by carefully timed 8051 assembly instructions.

## Features

- 8051 MCU compatible
- C + Assembly mixed implementation
- No PWM / SPI / DMA required
- Software generated WS2812B NRZ waveform
- Adjustable GPIO output pin
- Suitable for low-cost MCUs

## Architecture

![Driver Architecture](docs/driver_architecture.svg)

The driver consists of two layers:

### Application Layer

`main.c` prepares LED color data and stores it in `Data_Tab[]`.

### Timing Layer

`LED_driver.asm` generates the WS2812B waveform by controlling GPIO timing at instruction-cycle level.

## WS2812B Protocol

WS2812B uses a single-wire NRZ protocol. Each LED requires 24 bits of color data.

```
Green 8 bits
Red   8 bits
Blue  8 bits
```

Timing information is encoded by HIGH pulse width.

![WS2812B Timing](docs/ws2812b_timing.svg)

## Assembly Timing Engine

The core idea is to use the 8051 CPU itself as a waveform generator.

```
Instruction execution
          |
          v
GPIO HIGH / LOW timing
          |
          v
WS2812B data waveform
```

The driver uses NOP instructions to precisely adjust pulse width:

```asm
NOP
NOP
NOP
NOP
NOP
```

Different instruction paths generate different timing for bit 0 and bit 1.

## Data Flow

```
main.c
  |
  v
Data_Tab[]
  |
  v
LED_DRIVER()
  |
  v
GPIO P3.1
  |
  v
WS2812B DIN
```

## Buffer Configuration

Each LED requires 3 bytes:

```
1 LED = RGB = 3 bytes
```

Example:

```c
Uint8 idata Data_Tab[126] _at_ 0x80;
```

supports:

```
126 / 3 = 42 LEDs
```

If the LED count changes, update both the C buffer size and the assembly end address check.

## GPIO Configuration

The default output pin is:

```asm
PIN_NZR EQU P3.1
```

Modify this definition to change the output GPIO.

## Advantages

- Works on very small MCUs
- Requires only one GPIO pin
- Does not need special LED peripherals
- Demonstrates cycle-accurate embedded programming

## Limitations

- CPU is occupied during transmission
- Timing depends on MCU clock frequency
- Interrupts may affect waveform accuracy

## Porting

To port this driver:

1. Adjust GPIO operations
2. Recalculate instruction timing
3. Tune NOP delays
4. Verify waveform using oscilloscope or logic analyzer

## Project Idea

This project demonstrates how software timing can replace missing hardware peripherals in embedded systems by using precise CPU instruction execution control.
